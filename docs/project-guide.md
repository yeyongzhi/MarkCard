# MarkCard 项目说明书

> 版本：0.3 · 日期：2026-10-25 · 阶段：本地工作台重构
> 本文保留产品设计与验收约定。编辑、12 套模板、样式设置、分卡、PNG、本地保存与备份已在本地实现；GitHub Pages 工作流已配置，尚未推送或部署。技术方案见 [技术开发说明书](technical-design.md)。

## 1. 项目定位与决定

MarkCard 是将 Markdown 内容排版为精美图片卡片的网站，面向知识分享者、开发者、内容创作者和读书笔记用户。核心旅程是“输入内容 → 选择模板 → 调整外观 → 预览分卡 → 导出 PNG”。MarkCard 为依据当前目录采用的暂定名称。

| 事项       | 结论                                                                                                    | 状态                                   |
| ---------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 产品形态   | Markdown 转卡片的网站，强调多样模板与精美 UI                                                            | 已确认                                 |
| 基础模板   | 指定 shadcnui-vue-simple-template：Vue 3、TypeScript、Vite、Pinia、Vue Router、Tailwind CSS、shadcn-vue | 已确认                                 |
| 托管发布   | GitHub 仓库，通过 Actions 自动部署 GitHub Pages                                                         | 已确认                                 |
| 卡片与导出 | 单张长卡片、手动分卡、PNG 导出                                                                          | 已确认                                 |
| 外观功能   | 约 12 套风格；字体、配色、背景、尺寸、署名和代码高亮                                                    | 已确认                                 |
| 账号与数据 | 纯前端、无需登录、浏览器本地保存，无云端同步                                                            | 按用户授权开始执行的方案实施           |
| 平台与语言 | 桌面浏览器优先，兼顾手机；首期简体中文                                                                  | 建议方案                               |
| 仓库与分支 | https://github.com/yeyongzhi/MarkCard.git；本地 dev，先不推送                                           | 已确认；远程默认分支与自定义域名未核实 |

除上述已确认项外，后文的具体数量、交互、限制与里程碑均为建议方案，供开发执行前评审；不代表功能已交付。

## 2. 首期范围与完成标准

首期交付一个可静态托管的创作工具，覆盖编辑、模板、调整、手动分卡、PNG 导出和本地草稿。用户打开网站即可开始，不强制品牌水印。界面外观的浅色/深色模式与卡片本身配色分别设置。

首期不包含：账号、云端同步、公开作品社区、服务端图片代理、AI 写作、协作编辑、自动分页、PDF/JPEG 导出、任意自定义 CSS、公式与流程图。它们可在后续单独设计，避免将静态站点扩大为后端服务。

建议发布标准：12 套模板均有同内容预览并通过导出检查；桌面和手机能够完成核心旅程；长文本不静默截断；本地草稿能刷新恢复；主分支通过检查后可自动更新 Pages。

## 3. 页面与 UI 设计

### 3.1 创作工作台

首页直接进入工作台，首次展示可编辑的示例内容。顶部依次为标志与项目名、保存状态与设置操作、导出及复制单张卡片 PNG 入口。主体仅分为左侧 Markdown 输入、中间预览、右侧样式配置三部分；桌面两条分隔线支持鼠标拖动与键盘调整宽度。

右侧顶部使用“模板 / 排版 / 背景 / 署名”标签栏，模板直接在“模板”标签中选择，不打开弹窗。预览区只显示作品与底部右侧缩放工具，不显示预览标题、尺寸元信息、宣传文案或左下翻页控件；多张卡片纵向排列。缩放只改变查看大小，不改变导出像素。

手机以“编辑 / 预览 / 样式”Tabs 切换，设置直接在样式页展示；导出入口保持可达。页面在 375px 宽下不出现整体横向溢出；卡片允许在独立预览容器内缩放查看。

按用户最新决定，工作台使用 shadcn-vue 默认 Neutral 样式，不添加品牌主题色。html 根字号默认 16px，工作台及菜单、弹窗、提示等界面文字统一为 1rem，顶部 MarkCard 标题为 1.5rem；右上角全局设置可调整根字号与界面圆角，保存在 localStorage。卡片作品的排版字号和圆角独立，不受全局设置影响。顶部与底栏均为贴边、占满宽度且无圆角的工具栏；顶部由内容和少量上下内边距决定高度，底栏高 40px。底栏左侧展示年月日与实时钟，右侧提供预览缩放、百分比和适应画布控件。保留必要的异常反馈，移除装饰性中英文文案。

编辑器顶部工具栏保持单行、空间不足时横向滚动，提供撤销、重做、1–6 级标题、加粗、斜体、删除线、引用、有序/无序列表、链接、行内代码、代码块、表格、分隔线、手动分卡和本地图片。底部不再放文件选择区域。预览画布使用紧凑内边距，缩放适应宽度时计入该内边距。

### 3.2 建议模板目录

这些是首期设计方向，不是最终品牌素材。每套模板需同时规定背景、标题、正文、引用、列表、代码、表格和署名样式，不能仅更换背景色。

| 模板     | 视觉重点                     | 适合内容   |
| -------- | ---------------------------- | ---------- |
| 极简白   | 大留白、黑白层级、细分隔     | 日常知识   |
| 奶油纸   | 暖白纸感、衬线标题           | 阅读摘记   |
| 墨色夜读 | 深色底、柔和浅色正文         | 长文与夜读 |
| 薄荷清新 | 薄荷强调、轻盈引用块         | 生活清单   |
| 落日渐变 | 暖色渐变外框、实色内容面板   | 社交分享   |
| 极光紫   | 冷色光晕、明确标题区         | 灵感观点   |
| 终端代码 | 等宽装饰、终端式代码区域     | 开发笔记   |
| 杂志编辑 | 强标题、章节编号、编辑式留白 | 观点文章   |
| 蓝图笔记 | 淡网格、蓝色线条             | 技术解释   |
| 复古报刊 | 米白、黑色细线、报刊标题     | 文字随笔   |
| 手帐便签 | 浅纸色、边角装饰、柔和区块   | 摘录与清单 |
| 大字金句 | 大字号、短文留白、突出署名   | 引用与金句 |

所有模板都渲染完整 Markdown；“大字金句”等内容偏好只影响推荐，不自动删减长文。应用 UI 深色模式不自动反转导出卡片。

## 5. 业务规则与异常

- 分卡约定：独占一行的 `<!-- card-break -->` 为手动分卡标记；编辑区提供插入入口。仅围栏代码块外生效；普通 `---` 保持 Markdown 分隔线含义。连续或首尾标记产生的空段不导出，界面提示已忽略空卡。
- 首期为自适应高度卡片，宽度通过单个滑动条在 320–1440 CSS px 范围内以 10px 步长调整；不承诺固定比例下自动裁切。超长内容引导手动分卡或降低倍率，不能静默裁剪。
- 建议正文最大 100,000 字符，默认字号 16px、行高 1.0；字号可调范围 12–72px、行高 1.0–2.4、内边距 16–96px；超限提示并保留当前有效状态。实际安全上限在导出验证后调整并同步文档。
- 署名不超过 80 字符、来源不超过 200 字符；空正文可以预览空状态，但不可导出空卡。
- 本地图片建议单文件不超过 5MB、单项目合计不超过 20MB，仅支持 PNG/JPEG/WebP；SVG、GIF、远程图片暂不纳入首期。Markdown 的远程图片显示占位与本地替换提示，外部链接由用户主动点击打开。
- 宽表格和长代码在导出布局中换行或约束列宽；不能把预览中的横向滚动容器直接截成缺失内容的图片。
- 全部导出采用逐张生成、逐张下载，显示完成数量。浏览器阻止多文件下载时提示授权或改为逐张下载；首期不承诺 ZIP 打包。
- 本地草稿仅保留当前作品，保存正文、模板、样式、署名和图片；不承诺无限历史与跨设备恢复。清理浏览器数据或更换站点域名后可能无法恢复，应提供项目文件备份。
- 项目 JSON 是可携带备份，包含图片与版本字段；Markdown 下载只包含文本，本地图片标记不能独立恢复图片，下载前说明差异。

## 6. 典型使用流程

1. 打开工作台，首次使用查看示例；已有草稿则恢复并提示恢复时间。
2. 输入 Markdown，或导入 .md；需要替换现有内容时确认覆盖。
3. 打开模板库，选择风格，再调整排版、背景和署名。
4. 在需要分卡的位置插入分卡标记，逐张检查内容、代码和图片。
5. 选择 PNG 导出倍率。等待图片和字体就绪后下载；失败时按提示更换图片、降低倍率或增加分卡。
6. 下载项目 JSON 备份；下次导入可恢复相同作品设置与本地图片。

遇到本地保存失败时，持续保留内存中的编辑内容，展示固定提示并提供备份入口。切换模板不会要求重新输入正文。重置样式与清空作品是不同操作，只有后者删除内容并要求确认。

## 7. 隐私、可访问性与质量目标

按建议的纯前端方案，正文与图片在浏览器处理，不主动上传；页面本身仍从 GitHub Pages 下载静态资源。首期不接入统计、在线字体或图床；外部链接会访问目标站点。浏览器本地数据不等于加密保险箱，共用设备用户应主动清空草稿。

控件采用有标签的 shadcn-vue 组件，图标按钮提供可访问名称。正文输入使用 Textarea；预览不要求逐键朗读整篇内容，保存/导出状态适度播报。默认模板正文对比度以 WCAG AA 为目标，自选低对比颜色显示提醒但允许用户调整。

建议在 Chromium、Firefox、Safari 当前稳定版，以及 Android Chrome、iOS Safari 实机验证；导出失败提供可操作反馈。性能目标为 10,000 字符常规文本在约定测试设备上输入停止后 300ms 内完成预览；设备与基准在开发期记录，不能将目标当作测量结果。
